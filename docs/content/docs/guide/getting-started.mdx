# Quick Start

## Automatic setup (recommended)

`create-praxisjs` scaffolds a project with TypeScript, Vite, JSX, and HMR already configured. It's the fastest way to get started.

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
<Tab value="npm">
```sh
npm create praxisjs@latest
```
</Tab>
<Tab value="pnpm">
```sh
pnpm create praxisjs
```
</Tab>
<Tab value="yarn">
```sh
yarn create praxisjs
```
</Tab>
<Tab value="bun">
```sh
bun create praxisjs
```
</Tab>
</Tabs>

The CLI asks for a project name and a template:

| Template | What's included |
|---|---|
| **Minimal** | core, decorators, jsx, runtime |
| **With Router** | Minimal + router |
| **Full** | Router + store, di, composables, concurrent, devtools |

Start the dev server:

```sh
cd my-app
npm install
npm run dev
```

## Manual setup

Prefer to wire things up yourself? Here's what you need.

### 1. Install packages

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
<Tab value="npm">
```sh
npm install @praxisjs/core @praxisjs/jsx @praxisjs/runtime @praxisjs/decorators
npm install -D @praxisjs/vite-plugin
```
</Tab>
<Tab value="pnpm">
```sh
pnpm add @praxisjs/core @praxisjs/jsx @praxisjs/runtime @praxisjs/decorators
pnpm add -D @praxisjs/vite-plugin
```
</Tab>
<Tab value="yarn">
```sh
yarn add @praxisjs/core @praxisjs/jsx @praxisjs/runtime @praxisjs/decorators
yarn add -D @praxisjs/vite-plugin
```
</Tab>
<Tab value="bun">
```sh
bun add @praxisjs/core @praxisjs/jsx @praxisjs/runtime @praxisjs/decorators
bun add -d @praxisjs/vite-plugin
```
</Tab>
</Tabs>

### 2. Configure Vite

```ts
// vite.config.ts
import { defineConfig } from 'vite'
import { praxisjs } from '@praxisjs/vite-plugin'

export default defineConfig({
  plugins: [praxisjs({ hmr: true })],
})
```

### 3. Configure TypeScript

```json
// tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "jsxImportSource": "@praxisjs/jsx",
    "useDefineForClassFields": false,
    "strict": true,
    "noEmit": true
  }
}
```

<Callout type="warn" title="`useDefineForClassFields: false` is required">
  This is the most common setup mistake. With `true` (the TypeScript ES2022+ default), class fields compile as `Object.defineProperty`, which runs **after** decorator initializers and overwrites the signal getter/setter they registered. Setting it to `false` compiles fields as constructor assignments (`this.x = value`), keeping decorator wiring intact.
</Callout>

## Your first component

```tsx
// src/Counter.tsx
import { StatefulComponent } from '@praxisjs/core'
import { Component, State, Prop } from '@praxisjs/decorators'

@Component()
class Counter extends StatefulComponent {
  @Prop() initialCount = 0
  @State() count = 0

  onMount() {
    this.count = this.initialCount
  }

  render() {
    return (
      <div>
        <p>Count: {() => this.count}</p>
        <button onClick={() => this.count++}>+</button>
        <button onClick={() => this.count--}>−</button>
      </div>
    )
  }
}
```

<Callout type="info" title="Why {() => this.count} instead of {this.count}?">
  `render()` runs **once** on mount. Without the arrow function, `this.count` is read once at that moment and never updates. Wrapping it in `{() => this.count}` creates a live subscription: when `count` changes, only that specific `<p>` node updates.
</Callout>

<StorybookLink story="getting-started-counter--default" label="Counter — live demo" />

### Mount the app

```ts
// src/main.ts
import { render } from '@praxisjs/runtime'
import { Counter } from './Counter'

render(() => <Counter initialCount={5} />, document.getElementById('app')!)
```

## AI & MCP

[`@praxisjs/mcp`](/docs/tooling/mcp) gives any MCP-compatible AI assistant live access to praxisjs.org documentation. Two AI integrations are available:

| Integration | AI assistant | Project memory | Skill location |
|---|---|---|---|
| **Claude Code** | Claude Code, Cursor, VS Code/Copilot, Windsurf | `CLAUDE.md` | `.claude/skills/praxisjs/` |
| **Codex** | OpenAI Codex | `AGENTS.md` | `.agents/skills/praxisjs/` |

### New project

When scaffolding with `create-praxisjs`, the "Add an AI integration?" step lets you pick the integration — skill files and project memory file are configured automatically.

### Existing project

Run the `ai add` command in the project root:

<Tabs items={['npm', 'pnpm', 'yarn', 'bun']}>
<Tab value="npm">
```sh
npx praxisjs ai add
```
</Tab>
<Tab value="pnpm">
```sh
pnpm dlx praxisjs ai add
```
</Tab>
<Tab value="yarn">
```sh
yarn dlx praxisjs ai add
```
</Tab>
<Tab value="bun">
```sh
bunx praxisjs ai add
```
</Tab>
</Tabs>

Select the integration. For **Claude Code**, skill files are added to `.claude/skills/praxisjs/` with the MCP server pre-configured in `.claude/settings.json`. For **Codex**, skill files go to `.agents/skills/praxisjs/` and `AGENTS.md` is created at the project root (MCP is configured separately in `~/.codex/config.toml` — see the [MCP docs](/docs/tooling/mcp)).

To uninstall an integration, run `praxisjs ai remove` — see the [AI skills guide](/docs/guide/ai-skills#removing-a-skill) for what it does and doesn't delete.

### MCP server only

To add only the MCP server (without the Claude Code skill):

<PackageInstall pkg="@praxisjs/mcp" dev />

See the [MCP Server](/docs/tooling/mcp) page for client-specific setup (Cursor, VS Code/Copilot, Windsurf, Codex).
