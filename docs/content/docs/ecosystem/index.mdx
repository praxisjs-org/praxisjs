# Packages

All first-party packages use the same signal system and decorator conventions as core. They're completely independent of each other — install only what your project needs.

<Cards>
  <Card
    title="Document Head"

    href="/docs/essentials/head"
  />
  <Card
    title="Content"

    href="/docs/ecosystem/content"
  />
  <Card
    title="Router"
    description="Signal-based client-side routing. @Router sets up routes and layouts. @Route co-locates path with the page component. Reactive injectors for params, query, and navigation."

  />
  <Card
    title="Store"
    description="Class-based singleton state management. @Storable marks a class as a singleton store. @Store injects the shared instance into any component."
    href="/docs/ecosystem/store"
  />
  <Card
    title="Dependency Injection"
    description="@Injectable, @Inject, @Scope, and token-based injection. Scoped child containers per component instance. Circular dependency detection."
    href="/docs/ecosystem/di"
  />
  <Card
    title="Motion"
    description="Animated field decorators. @Tween for duration-based easing. @Spring for physics-based spring animation. Assign a value — the transition plays automatically."

  />
  <Card

## Choosing a package

| I need to… | Use |
|---|---|
| Set page title and meta tags per route | [Head](/docs/essentials/head) |
| Load and render markdown files | [Content](/docs/ecosystem/content) |
| Navigate between pages | [Router](/docs/ecosystem/router) |
| Share state across components | [Store](/docs/ecosystem/store) |
| Inject services into components | [DI](/docs/ecosystem/di) |
| Animate a value when it changes | [Motion](/docs/ecosystem/motion) |
| Model complex state transitions | [FSM](/docs/ecosystem/fsm) |
| Track loading/error state on async methods | [Concurrency](/docs/ecosystem/concurrency) |
